03 / ALGORITHM NOTES

How BFS explores the puzzle

A complete, level-by-level search for the fewest moves.

UNINFORMED SEARCH

The problem as a state space

The 8-puzzle has eight numbered tiles and one blank on a 3 × 3 grid. A state is the ordered arrangement of all nine cells. Legal actions slide the blank up, down, left, or right when that neighbor exists. Each action has unit cost.

The initial state is the starting board and the goal is the target. A board key (the nine digits) uniquely identifies a state. For a 3 × 3 puzzle, states are mutually reachable exactly when inversion parity relative to the goal's nonblank tile order matches.

FIFO queueExpand the oldest discovered state first; shallow states come first.
Visited setMark states when enqueued to prevent duplicate work.
Parent mapStore each state's predecessor and the blank move used.
ReconstructionFollow parents from goal to start, then reverse the sequence.

BFS in pseudocode

queue ← [start]
visited ← {start}
parent[start] ← null

while queue is not empty:
    state ← queue.popFront()
    if state = goal:
        return reconstruct(parent)

    for next in legalSuccessors(state):
        if next not in visited:
            visited.add(next)   // on enqueue
            parent[next] ← state
            queue.pushBack(next)

return no solution
Time O(bd+1)Space O(bd+1)

For branching factor b and shallowest goal depth d, O(b^(d+1)) is the standard worst-case time and space bound. The dequeue-time goal check can expand some depth-d states before the goal is reached. The finite graph has 9! permutations, with 181,440 reachable from a fixed valid state. BFS is complete and optimal for equal unit costs, but memory can be substantial.

Heuristics: BFS uses none. Misplaced-tile count and Manhattan distance are common heuristic examples for GBFS or A*, but this app does not implement or benchmark them.

Interactive 8-Puzzle Problem Solver using AI Search Algorithms

This static website models the 8-puzzle as a graph and runs a manually implemented BFS to demonstrate queue-based uninformed search. The interface records expansion events so learners can pause, step backward or forward, and inspect the frontier, explored set, and shortest path.

Built with HTML5, CSS3, Bootstrap 5, and vanilla JavaScript. It runs entirely in the browser and needs no backend. See README for local run, test, and GitHub Pages deployment instructions.
